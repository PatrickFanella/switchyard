# backend/internal/controlplane/

## Responsibility
Owns Switchyard's automation runtime: workflows, definitions, pipelines, triggers, runs, steps, events, artifacts, leases, retries, cancellation, Open Pilot policy, model/OpenCode adapters, HTTP APIs, and persistence.

## Design
- `Store` has matching memory and PostgreSQL implementations, split into `store_{workflows,runs,open_pilot,model_broker}.go` and `postgres_store_{workflows,runs,open_pilot,model_broker}.go`; shared store types and database helpers remain in `store.go` and `postgres_store.go`.
- `Runner` executes immutable pipeline snapshots through capability interfaces, records a resolved backend only immediately before an outbound attempt, and recovers previously running steps. `step_outputs.go` owns the durable named step output contract: `{{steps.<step_id>.outputs.<name>}}` references are validated at definition time, resolved deterministically before each step executes, bounded and redacted before persistence (`run_steps.outputs`, migration 029), and restored from succeeded step records on same-run retry, `retry_from_run` resume, and restart. `step_output_contract.go` turns a definition step `output_shape` into a versioned `output_contract` in the immutable pipeline snapshot, rejects shapes outside the supported subset on save/activate/rollback, validates bounded outputs before persistence and downstream consumption, and withholds restored outputs that fail the snapshot contract.
- `source_collection.go` implements the generic read-only `source` step executor and its first adapter, `gitea-activity` (`gitea_issue_activity.go`, limited by `SWITCHYARD_SOURCE_REPOSITORIES`): a run-anchored window, deduplication, stable ordering, item and byte caps, citation IDs, named outputs, and an attached evidence artifact. `model_grounding.go` makes a model step grounded when it declares `grounding_item_count`: zero items skips the model call, otherwise citations are checked against the collected IDs. `changemaker_definition.go` holds the grounded Changemaker digest definition and upgrades only an unmodified stored version 1.
- `WorkerPool` uses durable claims and renewable leases, recovers expired leases, retries with backoff, and terminalizes worker panics; `Scheduler` converts cron/poll triggers into queued or immediate runs.
- `EnvModelBroker` and `EnvOpenCodeExecutor` are Switchyard-native contracts with compatibility backends.
- `backend_decision.go` resolves native and deprecated backend routes; its atomic store recording attaches namespaced correlation metadata and deprecated-attempt events.
- Open Pilot and Devlog executors live in `executor_open_pilot.go` and `executor_devlog.go`; the unreachable external Changemaker executor is removed, while adapter migration probing remains read-only. `devlog_evidence.go` owns Devlog repository-evidence mode: allowlisted `repositories`/`since`/`until` inputs (Open Pilot registry plus `DEVLOG_ALLOWED_REPOS`), bounded paged collection through the read-only `gitea_activity.go` methods on the shared Gitea client, deduplication, merged/deployed/proposed classification, missing-source reporting, and the `devlog-evidence.json` artifact.
- `open_pilot_repository_registry.go` owns strict v1 registry/manifest decoding and target parsing. `open_pilot_admission.go` enforces legacy-singleton, disabled, isolated-test, or database-backed durable admission. `open_pilot_execution_registry.go` binds admitted runs to immutable repository/generation-specific OpenCode, verifier, and worktree bundles; `open_pilot_repository_status.go` projects bounded per-repository health. `open_pilot_rollout.go` and the rollout store files own proof/allow, expiry, claim fencing, and rollback evidence. `open_pilot_inbox.go` builds the bounded, read-only control-only issue inbox: admitted-repository Gitea listings (labels and bot assignee), durable claims, pickup/specification/command/claim reason codes, upstream availability, filters, and cursor pagination; it never claims or dispatches. `open_pilot_audit.go` builds the bounded control-only repository audit report. `open_pilot_readiness.go` composes registration, generation, rollout, executor health, issue affinity, command allowlist, and lifecycle gates into the readiness preflight with stable reason codes, an onboarding checklist, and dry-run configuration validation. Migrations 025-027 add rollback-compatible affinity, monotonic alias candidates, and the durable rollout singleton without replacing `(repo, issue)` uniqueness; workers atomically adopt safe migrated runs before execution or lease recovery.
- `evidence_search.go` defines the bounded evidence-search contract (scopes, filters, retention floor, keyset cursor, redaction) and its control-only handler; `store_evidence_search.go` and `postgres_store_evidence_search.go` implement it with shared matcher semantics, and migration 028 adds the `(created_at, id)` indexes it scans.
- HTTP registration is in `http_routes.go`; run/trigger, workflow-definition, agent-profile, Open Pilot lifecycle, and CORS handling are in `http_runs.go`, `http_workflow_definitions.go`, `http_agent_profiles.go`, `http_open_pilot.go`, and `http_middleware.go`.
- `profiles.go` defines agent-profile identity, immutable versions, provenance, validation, and the store-backed registry that prefers the active persisted version over shipped static defaults; `store_profiles.go` and `postgres_store_profiles.go` (migration 029) persist versions and the append-only audit ledger. Run creation copies effective profiles into `pipeline_snapshot.profiles` so activation or rollback never changes an in-flight run.
- `http_runtime_config.go` serves the control-only effective-configuration view from the runtimeconfig inventory (secret values redacted by classification) and the admin-only, revision-checked runtime pauses for the scheduler and worker pool; accepted changes are logged and kept in a bounded process-local list.
- Status providers expose configured versus effective selector and transitional compatibility metadata; listener boundaries prevent model ingress from exposing operator/admin routes. `correlation_targets.go` sanitizes `GITEA_BASE_URL` and `SWITCHYARD_TRACE_UI_URL` (scheme, host, path only) for the control-only `/api/operator-safety` payload, which the dashboard uses as its correlation link allowlist.
- PostgreSQL `ModelService` ownership uses a watched dedicated advisory-lock session. Session or lock loss permanently poisons the old runtime, cancels active requests and workers, and fails readiness and broker operations before a replacement owner serves work.
- Operator and broker observability use bounded storage projections: PostgreSQL aggregates counts/latency and returns only capped recent rows, while memory mirrors the contract for local use.
- Artifacts are validated inline data URIs with persisted storage, MIME, decoded-size, SHA-256, and retention metadata. PostgreSQL triggers always maintain exact retained aggregates; a transaction-local writer setting selects trigger lifecycle accounting without double-counting rolling pre-023 writers. Deprecated backend usage and explicit revision/deployment-bound UTC daily observation coverage use separate tables and survive run retention.

## Flow
1. `SeedDefaults` creates first-party workflows, triggers, and workflow definitions.
2. API/scheduler validates inputs and creates a run with a pipeline snapshot.
3. A worker claims the run, renews its lease, and calls `Runner.ExecuteClaimedRun`.
4. The runner orders steps, resolves models/profiles, enforces executor limits, and dispatches workflow capabilities.
5. Each transition writes step status, events, artifacts, correlations, and final run status; backend evidence is written atomically before external work, while failures, panics, and expired leases close or retry work safely.
6. APIs expose control state and compatibility model/OpenCode surfaces; retention prunes old records.

## Integration
- Called by both Go commands and consumed remotely by `web/`.
- Persists through PostgreSQL schemas in `migrations/`; can use in-memory state for local runs.
- Integrates with managed OpenCode, Ollama/llama-line, Gitea, Git, command execution, and OTEL spans.
- Important entry points: `http.go`, `http_routes.go`, `http_runs.go`, `http_workflow_definitions.go`, `http_open_pilot.go`, `runner.go`, `executor.go`, `executor_open_pilot.go`, `executor_devlog.go`, `backend_decision.go`, `store.go`, `postgres_store.go`, `pipeline.go`, `worker.go`, `scheduler.go`.
