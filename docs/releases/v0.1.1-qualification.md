## Rollback decision

Do not use `v0.1.0` as a rollback target: it is the release whose strict
OpenCode startup failed against existing persisted production state. The older
`53733c6` revision is untagged, unqualified, and would remove production
executor hardening.

`v0.1.1` becomes the known-good application rollback target after a separately
qualified successor is promoted. The live application rollback obligation
cannot be closed safely while `v0.1.1` is itself the active release.
